# 02 · Tool use (модель вызывает функцию)

[Уроки](../README.md#уроки) · [← 01](./01-note-sorter.md) · [03 →](./03-ollama.md)

## Зачем
Классификация из урока 01 ничего не сохраняет. В продукте нужен побочный эффект: запись в базу. Модель **выбирает действие и аргументы**, твой код **выполняет** его. Иначе модель «сказала, что сохранила», а в БД пусто.

## Простыми словами
**Tool use / function calling** - модель не пишет свободный ответ, а заполняет карточку вызова: имя функции + поля. Как заказ на кухню: официант (модель) заполняет бланк, повар (твой код) готовит.

В этом уроке одна функция: `save_note(text, category, urgent)` → строка в SQLite.

Важно: в базу кладём **исходный текст пользователя**, не пересказ модели. Иначе модель может «улучшить» формулировку и потерять смысл.

## Как сделали
| Файл | Роль |
|---|---|
| `02-tool-use/agent.py` | описание tool, вызов LLM, Pydantic по аргументам, INSERT |
| `02-tool-use/app.py` | поле ввода + таблица последних заметок |
| `02-tool-use/notes.db` | SQLite (в git не кладём) |

GigaChat здесь ждёт старый формат `functions` (не OpenAI `tools`). Принудительно: `function_call={"name": "save_note"}`.

## Как работает
1. Пользователь пишет заметку.
2. В API уходит system prompt + схема `save_note`.
3. Модель отвечает `function_call`, не текстом.
4. Аргументы проверяем через `SaveNoteArgs`.
5. Код делает `INSERT` в `notes`. `text=` всегда исходная строка.
6. UI читает таблицу `list_notes`.

Цепочка: **модель решила категорию → код записал строку**.

## Что потрогать
```bash
python 02-tool-use/agent.py "Завтра созвон с инвесторами"
```
Hub → **02 Tool Use** или `npm run 02`.

## Готово, когда
- [ ] В `notes.db` появляется строка после нажатия
- [ ] Понимаешь: без tool это был бы только JSON на экране
- [ ] Не путаешь «модель вызвала функцию» и «модель сама ходила в SQLite» (второго нет)

## Что запомнить
Побочные эффекты только в твоём коде. Модель заполняет бланк, ты исполняешь.
