# 03 · Local LLM (Ollama)

[Уроки](../README.md#уроки) · [← 02](./02-tool-use.md) · [04 →](./04-gym-plan.md)

## Зачем
На рынке (особенно on-prem) модель часто крутят **у себя**: данные не улетают в облако, нет счёта за токены. Ollama - самый простой способ поднять локальную LLM.

## Простыми словами
Ollama - программа на компьютере. Она качает модель (файлы весов) и отдаёт **тот же стиль API**, что OpenAI: `chat.completions`. Наш код в `lib/llm.py` не переписываем: меняется адрес и имя модели.

Облако: `https://api.giga.chat/v1` + ключ.  
Дома: `http://localhost:11434/v1` + модель вроде `qwen2.5:3b`.

Переключатель в `.env`: `LLM_PROVIDER=ollama` или `gigachat`. Ключи `GIGACHAT_*` и `OLLAMA_*` лежат рядом, их не трут друг друга.

## Как сделали
| Файл | Роль |
|---|---|
| `03-ollama/check.py` | ping сервера + та же `categorize_note`, что в уроке 01 |
| `03-ollama/app.py` | тот же сортировщик, но подпись «local» |
| `scripts/start-ollama.sh` | запуск + `ollama pull` дефолтной модели |
| `scripts/stop-ollama.sh` | остановить, освободить RAM |
| `scripts/set_provider.py` | одна строка в `.env` |

Логика классификации **не копировалась** - импорт из `01-note-sorter/categorize.py`. Урок про провайдера, не про новый промпт.

## Как работает
1. `ollama serve` слушает порт 11434.
2. В RAM лежит модель (3B занимает порядка 2 ГБ).
3. `.env` → `LLM_PROVIDER=ollama` → `lib/llm.py` собирает OpenAI-клиент на localhost.
4. Сортировщик шлёт тот же JSON-запрос.
5. Ответ снова проходит через Pydantic.

Если Ollama выключен - будет ошибка соединения, не «тихий» облачный фолбэк.

## Что потрогать
```bash
npm run ollama:start          # brew install ollama - один раз
npm run provider:ollama
python 03-ollama/check.py "купить хлеб сегодня"
```
Hub → **03 Ollama** или `npm run 03`.

Вернуться в облако: `npm run provider:gigachat`. Сервер можно выключить: `npm run ollama:stop`.

## Что запомнить
Провайдер - конфиг, не форк приложения. Local = тот же контракт JSON, другие железо и задержка.
