# 01 · Сортировщик заметок

[Уроки](../README.md#уроки) · след. [02 Tool use](./02-tool-use.md)

## Зачем
Модель в продукте - не чат, а функция: на вход текст, на выход два поля. Иначе UI и база ломаются от свободного ответа.

## Простыми словами
Ты пишешь заметку («завтра созвон»). Код просит модель вернуть **только JSON**: категория и срочность. Потом **Pydantic** проверяет, что поля именно такие, а не «ну вроде работа». Если схема не сошлась - ошибка, в интерфейс мусор не попадает.

- **System prompt** - правила сервиса (не болтовня).
- **temperature=0** - для классификации меньше фантазии.
- **Pydantic** - проверка на границе доверия: модели не верим на слово.

## Как сделали
| Файл | Роль |
|---|---|
| `01-note-sorter/categorize.py` | промпт + вызов LLM + разбор JSON |
| `01-note-sorter/app.py` | экран: текст или диктовка → результат |
| `lib/llm.py` | клиент GigaChat или Ollama из `.env` |

Категории только три: `WORK` / `PERSONAL` / `SHOPPING`. `urgent=true` только если дело ещё впереди и срок близкий («сегодня», «завтра», «срочно»). «Вчера срочно купил» - уже не срочно.

## Как работает
1. Берём текст заметки.
2. Шлём system + user в чат-API (`json_object`, если провайдер умеет).
3. Вырезаем markdown-обёртку `` ```json ``, если модель её приклеила.
4. `NoteClassification.model_validate_json(...)` - либо объект, либо ошибка.
5. UI показывает категорию и срочность.

Пример:

```json
{"category": "SHOPPING", "urgent": true}
```

для «сегодня вечером заехать за кормом».

## Что потрогать
```bash
python 01-note-sorter/categorize.py "Надо купить хлеб"
```
Hub → **01 Сортировщик** или `npm run 01`.

## Готово, когда
- [ ] Понимаешь: промпт = контракт, не «будь умным»
- [ ] Видишь, что без Pydantic в UI мог бы приехать любой текст
- [ ] Можешь объяснить, почему temperature здесь 0

## Что запомнить
LLM в продукте отвечает схемой. Проверка схемы - твой код, не модель.
